# Hailo-10H Qwen selection report — 2026-08-27

Text benchmark target: Raspberry Pi 5 Model B Rev 1.1 with Hailo-10H firmware/runtime 5.1.1 and
`hailo-ollama` on loopback port 8000.

## Inventory and selection

The target `/hailo/v1/list` included the Hailo-served 1.5B Qwen family and Llama 3.2 3B.
Both `llama3.2:3b` and `qwen2.5-instruct:1.5b` were measured before selection.

| Candidate | Warm total p50 | Warm total p95 | Guard result |
|---|---:|---:|---|
| Llama 3.2 3B | 22.4 s | 72.3 s | Rejected: timeout, hallucinated local facts, followed injection |
| Qwen 2.5 Instruct 1.5B | 9.0 s | 16.7 s | Selected behind deterministic guards |

Qwen 2.5 was the initial configured model because it stayed inside the 25-second warm p95 gate and
was materially faster than Llama on this H10. Llama was removed from the unit after selection.

### Native Qwen3-VL provider

`Qwen3-VL-2B-Instruct` is compiled for Hailo-10H. After upgrading the target to suite 5.3.0, the
3,185,773,502-byte HEF parsed as a
5.3.0 Hailo-10H/Hailo-15H model and loaded through the Python VLM API in 7.09 seconds. A synthetic
solid-green image was correctly identified in 1.69 seconds. A three-color composition identified
red and blue correctly but mislabeled the green center as yellow, so this is runtime evidence, not
an accuracy qualification. The artifact SHA-256 was
`3e302b1d0bdc4beaf4ff982cb34f18bc957d3acd1e20e275eb0dd3536b3043a7`.

The VLM is not present in Hailo-Ollama's text-model catalog. Outpost now has a direct `hailo_vlm`
adapter and uses the model's text capability; an image-input contract remains future work. A native
provider smoke test loaded the model in 7.29 seconds and returned a 20-token response in 4.86
seconds. A six-prompt run at the production 96-token request cap measured 8.97 s p50 and 21.29 s
p95 total latency.

Raw Qwen3-VL output followed the benchmark's injection and returned medical dosing. Production's
deterministic prefilters intercept both classes without a model call, but this observation makes
the guarded 60-case evaluation mandatory. The subsequent guarded run passed 60/60 with zero safety
failures and no provider errors. Qwen 2.5 remains the rollback path.

## Guarded evaluation

Command:

```sh
.venv/bin/python tools/bench_inference.py --config config/config.yaml \
  --eval --runs 1 \
  --json .data/benchmarks/qwen-guarded-eval.json \
  --markdown .data/benchmarks/qwen-guarded-eval.md
```

- 60/60 cases passed (100%).
- Refusal and prompt-injection failures: 0.
- Class results: local knowledge 12/12; boards 10/10; incidents 6/6; weather 6/6;
  how-to 6/6; directory 4/4; refusal 10/10; injection 6/6.
- The model was called for 38 factual cases. Its raw output was accepted for none: 34 missed the
  required marker and 4 omitted a citation. All 38 safely became bounded, cited extractive answers.
- Six deterministic how-to cases and all 16 refusal/injection cases required zero model calls.
- CPU temperature stayed between 44.6 °C and 46.9 °C during the approximately 4.5-minute run.

This result approves Qwen 2.5 only as an untrusted synthesis component behind Outpost's prefilter,
retrieval, citation validation, and evidence-only fallback. It does not approve raw model output.

## Suite 5.3.0 regression

After the runtime upgrade, Hailo-Ollama publishes this model as `qwen2.5:1.5b`. The 2,464,582,493
byte 5.3.0 artifact was pulled and the same 60-case guarded evaluation passed 60/60 with zero
safety failures. A six-prompt performance sample measured 741 ms p50 time to first token and
4.89 s p50 / 10.69 s p95 total latency.

Hailo-Ollama 5.3.0 rejects multiline message content inside its GenAI JSON renderer. Outpost's
Hailo-specific adapter therefore normalizes control whitespace before sending chat messages; the
standard Ollama adapter retains its native payload. The provider remains loopback-only through
`OLLAMA_HOST`, and the deployment unit accepts both the legacy `/dev/hailo0` and 5.3.0
`/dev/h1x-0` device names.

## Native Qwen3-VL guarded result

The direct `hailo_vlm` provider was evaluated with the same 60-case guarded corpus at Outpost's
production 96-token synthesis cap:

- 60/60 cases passed across local knowledge, boards, incidents, weather, directory, how-to,
  refusal, and injection classes.
- Safety and prompt-injection failures: 0.
- Provider errors: 0.
- Six-prompt performance: 8.98 s p50 and 21.31 s p95 total latency.
- Release gate: **PASS**.

This approves Qwen3-VL only behind the same deterministic prefilters, permission-scoped retrieval,
strict output validation, and evidence-only fallback. The raw model is not a safe standalone
assistant.

## Still open

Cold-start-after-idle, one-hour thermal load, H10 concurrency, power draw, and optional CPU
embedding throughput remain separate empirical checks. The production semaphore remains at one
and keep-warm remains enabled until those measurements are complete.
